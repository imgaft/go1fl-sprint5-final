# Модуль фитнес-трекера

Проектная работа по курсу «Основы Go». Приложение обрабатывает записи о дневной активности и тренировках, рассчитывает пройденную дистанцию, среднюю скорость и расход калорий, формирует текстовый отчёт и сообщает об ошибках во входных данных.

## 1. Задача

Реализовать недостающую функциональность готового каркаса фитнес-трекера, сохранив его структуру, точку входа и предоставленные модульные тесты. Для дневной активности и тренировок предусмотреть общий способ обработки данных через интерфейс.

## 2. Что реализовано

Работа выполнена по функциональным блокам:

| Этап | Пакет | Выполненная работа |
| --- | --- | --- |
| 1 | `internal/spentenergy` | Реализованы функции `Distance`, `MeanSpeed`, `RunningSpentCalories` и `WalkingSpentCalories`: расчёт дистанции, средней скорости и энергозатрат. |
| 2 | `internal/personaldata` | Определена структура `Personal` с полями имени, веса и роста; реализован метод `Print` для вывода данных пользователя. |
| 3 | `internal/daysteps` | Реализована структура `DaySteps`, разбор строки дневной активности методом `Parse` и формирование отчёта методом `ActionInfo`. |
| 4 | `internal/trainings` | Реализована структура `Training`, разбор количества шагов, типа тренировки и длительности; расчёт показателей ходьбы и бега. |
| 5 | `internal/actioninfo` | Определён интерфейс `DataParser` и реализована функция `Info` для последовательной обработки записей и вывода результатов. |

При реализации использованы структуры и встраивание (`Personal` в `DaySteps` и `Training`), методы с получателями, интерфейс, функции стандартной библиотеки и явная обработка ошибок через `error`.

## 3. Как устроена обработка

1. В `cmd/tracker/main.go` задаются персональные данные пользователя и два набора входных строк: дневная активность и тренировки.
2. Для каждого набора создаётся соответствующая структура (`DaySteps` или `Training`) со встроенными персональными данными.
3. Функция `actioninfo.Info` последовательно передаёт строки в метод `Parse` через интерфейс `DataParser`.
4. `Parse` проверяет число полей, преобразует шаги в `int`, а длительность — в `time.Duration`. Некорректные значения приводят к возврату ошибки.
5. Если разбор успешен, метод `ActionInfo` обращается к функциям пакета `spentenergy` и формирует строку отчёта.
6. `Info` выводит отчёт. Если разбор или расчёт завершился ошибкой, ошибка записывается в журнал, а обработка продолжается со следующей строки.

### Расчёты

- **Дистанция, км:** `steps × height × 0.45 / 1000`.
- **Средняя скорость, км/ч:** `distance / duration.Hours()`.
- **Калории при беге:** `weight × speed × duration.Minutes() / 60`.
- **Калории при ходьбе:** половина рассчитанного расхода калорий при беге.

Рост передаётся в метрах, вес — в килограммах, продолжительность — в `time.Duration`.

В каждом из пяти каталогов `internal` находятся файл реализации и соответствующий файл `*_test.go`.

## 5. Запуск и ожидаемый результат

**Требования:** Go 1.24.1 или новее; зависимости описаны в `go.mod`.

Из корня репозитория выполнить:

```bash
go run ./cmd/tracker
```

Программа последовательно выводит два раздела: **«Активность в течение дня»** и **«Журнал тренировок»**. Для демонстрационного пользователя выводятся имя `Витя`, вес `84.60` кг и рост `1.87` м.

Пример результата для одной записи дневной активности:

```text
Количество шагов: 678.
Дистанция составила 0.57 км.
Вы сожгли 24.13 ккал.
```

Пример результата для одной записи тренировки:

```text
Тип тренировки: Ходьба
Длительность: 3.00 ч.
Дистанция: 2.91 км.
Скорость: 0.97 км/ч
Сожгли калорий: 123.02
```

Для других корректных записей программа аналогично рассчитывает показатели бега и ходьбы. В исходных демонстрационных наборах также есть намеренно некорректные строки. Для них выводятся диагностические сообщения (например, `неверный формат данных` или `invalid syntax`), после чего обработка остальных записей продолжается. Эти сообщения сами по себе не означают аварийное завершение программы.

## 6. Проверка результата

Запуск всех модульных тестов без использования кеша:

```bash
go test -count=1 ./...
```

**Результат локальной проверки:** все пять пакетов с тестами завершились со статусом `ok`:

```text
ok  github.com/Yandex-Practicum/tracker/internal/actioninfo
ok  github.com/Yandex-Practicum/tracker/internal/daysteps
ok  github.com/Yandex-Practicum/tracker/internal/personaldata
ok  github.com/Yandex-Practicum/tracker/internal/spentenergy
ok  github.com/Yandex-Practicum/tracker/internal/trainings
```

Для `cmd/tracker` выводится `[no test files]`: в точке входа отдельных тестов нет. Приложение дополнительно проверено командой `go run ./cmd/tracker` — вывод формируется, корректные записи обрабатываются, некорректные не прерывают выполнение.

Дополнительные проверки перед сдачей:

```bash
gofmt -l internal/
go vet ./...
```

Первая команда показывает файлы, требующие форматирования; вторая выполняет статический анализ. Результаты этих двух проверок следует оценивать отдельно от уже пройденных модульных тестов.

## 7. Итог

Реализованы все пять функциональных пакетов модуля фитнес-трекера. Приложение обрабатывает дневную активность и тренировки через единый интерфейс, рассчитывает показатели физической активности, выводит отчёты и обрабатывает ошибки входных данных. Предоставленные модульные тесты успешно пройдены; демонстрационный запуск выполнен.
